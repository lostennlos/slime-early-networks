# 菌路 · 早期丰富形态实验台 v4

2026-11-10 · `slime-early-networks-v4`

这次研究把用户认可的 P1 早期路网作为目标：保留较丰富的分叉、环路和宽窄变化，并让选定的早期形态成为正式结果。

## 打开与使用

双击 `outputs/黏菌路网_v4_早期丰富形态实验台.html`。网页完全离线，无需安装、联网或启动服务器。源码入口为 `dist/index.html`。

默认打开后会自动生成种子 42、A 布局的第 60 步网络：23/23 资源连通、24 条新增替代走廊、5421 格道路面积、宽度中位数 3 格。它的网络数据与用户认可的 P1 相同。

- **换个种子**：固定地图及资源布局，只改变粒子探索。
- **比较早期候选**：点击下方的时刻卡片保留另一帧，再点“选回自动推荐”恢复推荐。
- **生成蓝本状态**：恢复原固定快照、A 布局、种子 42 和默认设置。
- **三种视图**：自然道路带、连接与替代走廊、这一时刻的轨迹场。三者均显示同一候选时刻的数据。
- **保存与读取**：导出所选结果 JSON，或读取已有实验及固定地图；PNG 导出当前视图。大图显示资源编号，窄屏优先显示路网。
- **旧版配置**：读取 v1/v2/v3 配置后使用其地形与探索参数，按新的早期策略重新生成，不继续展示原来的后期网络。

## 与 v3 的区别

v3 的局部运动、资源吸引与消耗、沉积饱和、近期支持、真实行走图及道路提取保留不变。`dist/slime-v3.js` 是字节一致的基础计算模块。

v4 新增了独立的**早期候选选择与保留算法**。这次改变的是研究目标、候选评估、停止时机和输出保留方式，不将后期逐渐简化的网络当作最终目标，也不声称改造了底层生物模型。

默认流程：

1. 粒子从第 1 步开始探索；运动与道路使用记录照常累积。
2. 在第 48～120 步内，每 6 步保留候选；偏好时刻和窗口末端也会进入候选。
3. 先根据地形通行掩码计算资源实际可达分组，检查每个可达组内已有连接是否保留。连通充分的候选优先于不完整候选。
4. 再比较候选与 P1 的指标差距：全图替代走廊密度、道路覆盖比例、宽度中位数、宽度变化以及偏好时刻。
5. 若候选满足连通要求且参考指标偏差为零，提前保留；否则在窗口结束后保留最佳候选。
6. 保留后不再推进模拟。点击候选卡片可选择另一份已保存的早期结果；生成新路网需要明确重新生成。

默认种子 42 在第 60 步达到蓝本指标，因此此时即结束。B 布局会比较到 120 步，但默认保留的是第 66 步，显示其当时的路网和场，而不是把 120 步的场叠到早期道路上。

用户也可以在生成过程中选择“保留当前最佳候选”。尚未连通、资源点受阻或地形分隔的情况会如实显示，不补画未经探索的连接。

## 候选指标及参数

| 选择参数 | 默认值 |
|---|---:|
| 候选起点 `startStep` | 48 步 |
| 偏好时刻 `preferredStep` | 60 步 |
| 探索上限 `endStep` | 120 步 |
| 候选间隔 `interval` | 6 步 |
| 丰富度目标倍率 `richness` | 1 |

必须满足起点 ≤ 偏好时刻 ≤ 上限。此实验的早期探索上限最多为 240 步，窗口与最终运行百分比无关。

蓝本在 192×192 网格上有 23 个资源点，走廊密度为 24/23，道路占可通行格的约 15.7%，宽度中位数为 3 格，宽度 P90−P10 为 7 格。**15.7% 是道路覆盖比例，不是开始记录的时间比例。**

在满足连通要求的候选中，形态偏差使用以下加权相对差距：

| 项目 | 权重 |
|---|---:|
| 替代走廊密度 | 0.50 |
| 道路覆盖比例 | 0.25 |
| 宽度中位数 | 0.15 |
| 宽度变化 | 0.05 |
| 与偏好时刻的距离 | 0.05 |

较小的指标偏差表示这组形态统计更接近用户蓝本，不是图像逐像素相似度、最短路线评分或游戏质量评分。不同种子会实际生长出不同的路网。

宽度仍是网格形态指标，弯道和交汇区的数值可能较大，不能直接当成游戏道路米数。替代走廊数量为全图新增走廊数，不是每对资源之间的路径数量。

## 实际验证

使用两种固定布局和种子 42、7、99、1337，共 8 组。自动选择的结果位于 54～72 步，全部保持 23/23 资源连通，新增替代走廊为 23～25 条，并有宽度变化。

| 种子 | 布局 | 选择时刻 | 新增走廊 | 道路面积／格 |
|---|---|---:|---:|---:|
| 42 | A | 60 | 24 | 5421 |
| 42 | B | 66 | 24 | 5536 |
| 7 | A | 66 | 23 | 5316 |
| 7 | B | 54 | 24 | 5103 |
| 99 | A | 60 | 24 | 5317 |
| 99 | B | 72 | 24 | 5454 |
| 1337 | A | 60 | 25 | 5521 |
| 1337 | B | 60 | 23 | 5406 |

同时验证：

- 默认结果与 P1 的第 60 步完整网络数据相同。
- 结果保留后，再请求推进 1000 次，路网与场保持不变。
- 所有结果边在候选生成时就存在于真实行走记录中；连通分组、必要弱桥和障碍约束仍保留。
- JSON 重放恢复同一候选的道路和场，手动选择另一帧也可恢复。
- 永久墙两侧分别可达时，不伪称跨墙全连通；资源点本身受阻时标记未完成。
- 改变显示提取频率或交汇参考点，不改变粒子运动。
- 不同种子生成不同的实走路网，未复制蓝本图形。

结果详见 `outputs/validation.json`。上述八组来自同一固定地形的两种资源布局，不是跨地形普遍保证，也尚未验证真实玩家体验。候选评分是用户偏好驱动的工程选择，不是对生物最优行为的证明。

## 开发与复现

Node.js 仅用于开发、测试和构建；使用离线网页不需要 Node.js。

```text
node tests/early.test.cjs
node tests/import.test.cjs
node build.cjs
```

核心文件：

- `dist/early.js`：可达分组、早期候选评估、选择、保留及 JSON 重放。
- `dist/slime-v3.js`：原有局部探索及真实边道路提取内核。
- `dist/reference.js`：由实际第 60 步计算得到的 P1 指标、网络和场。
- `dist/context.js`：固定地形及两种资源布局。
- `dist/app.js`：候选比较、双语、显示与本地导入导出。

保存格式为 `slime-early-experiment-v1`，模型为 `slime-early-networks-v4`。读取配置时按参数和时刻重新计算，附带的几何数据不作为可信补路输入。

浏览器实际检查了默认结果、手动候选切换、种子与布局切换、三种视图、双语、无效窗口处理及 PNG/JSON 导出。读取适配器另用真实代码配合 UI 回调替身测试了 v4 重放、手动候选、v3 后期配置迁移及非法输入；原生文件选择对话框没有重复自动操作。详细记录见 `outputs/browser-validation.json` 与 `outputs/import-validation.json`。
